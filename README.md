LifeLine— Neonatal Telemedicine & Research Platform

A working v1 covering **Patient Data Management** end-to-end (register →
vitals/follow-up → teleconsultation request → outcome), plus a starter
**Research Dashboard** with descriptive stats. Everything else in the brief
(WebRTC video, full statistical tests, ML risk model, PDF/Excel reports) is
stubbed or scaffolded so you can build directly on top of this.

## Stack
- **Backend:** Python (FastAPI) + SQLAlchemy + SQLite
- **Frontend:** React (Vite) + React Router
- No auth yet — add before any real deployment.

## What's implemented
- Newborn registration (birth weight, gestational age, Apgar, complications, outcome)
- Follow-up vitals entries per patient
- Consultation *requests* + doctor's notes (no video yet — WebRTC hook point is in `PatientDetail.jsx`)
- Rule-based risk level (Low/Medium/High) on birth weight, gestational age, Apgar — used as the training label until real outcome data is available
- **Research dashboard** (`/`): summary stats + real charts (recharts) — mortality by birth-weight band, centre-wise mortality, birth weight vs. gestational age scatter colored by risk
- **Statistical analysis** (`/analysis`): descriptive stats (mean/median/SD), Pearson correlation between any two numeric fields, chi-square test of independence between any two categorical fields, logistic regression for mortality (coefficients, odds ratios, 95% CIs, p-values via statsmodels), 95% confidence intervals (Wilson for proportions, t-interval for means)
- **ML risk model** (`/risk-model`): trains a Random Forest or Logistic Regression classifier on demand, reports accuracy/precision/recall/F1 (macro)/ROC-AUC and a confusion matrix, and predicts risk level + class probabilities for a new case
- Demo data seed script (`backend/scripts/seed_demo_data.py`) — synthetic patients so stats/ML have something to run on immediately

## What's NOT built yet (your next additions)
1. **WebRTC video** — `Consultation` records exist; add a signaling server + video component in `PatientDetail.jsx`.
2. **Research Reports** — CSV/Excel (pandas `.to_csv`/`.to_excel`) and PDF (e.g. `reportlab` or `weasyprint`) export endpoints, pulling from the `/analysis` and `/stats` endpoints.
3. **Real risk labels** — the ML model currently trains on the rule-derived `risk_level` (see the `note` field in `POST /api/ml/train`'s response), so its high accuracy mostly proves it learned the rule. Swap in clinician-confirmed or outcome-validated labels for a metric that reflects real predictive value.
4. **Auth & roles** — health worker / doctor / researcher access levels.
5. **Persisted ML model** — the trained model currently lives in memory and resets when the backend restarts; persist with `joblib.dump`/`joblib.load` (already a dependency) before relying on it.

## Try the stats/ML modules with demo data
The real charts and models need actual data. From `backend/` (with the venv active):
```bash
python scripts/seed_demo_data.py 150
```
This generates 150 synthetic patients with realistic, correlated risk factors and outcomes — enough to exercise every chart, statistical test, and the ML model meaningfully. It's clearly synthetic (`Baby 001`, `Baby 002`, ...) so it won't be confused with real records.

## Running it locally

### Backend
```bash
cd backend
python3 -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```
API runs at `http://localhost:8000`. Interactive docs at `http://localhost:8000/docs` (auto-generated by FastAPI — useful while you build new endpoints).

The SQLite file (`neosankalp.db`) is created automatically on first run in `backend/`.

### Frontend
```bash
cd frontend
npm install
npm run dev
```
Runs at `http://localhost:5173`. Make sure the backend is running first (CORS is pre-configured for this port).
